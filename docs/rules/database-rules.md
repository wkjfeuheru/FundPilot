# 数据库设计规范

适用 MySQL 8.0 + InnoDB｜`MUST` 必须 / `SHOULD` 应当 / `NEVER` 禁止

## 一、目的与基本原则

- 目的：约束产出的 DDL 与 SQL，保证命名一致、变更可回滚、规则可校验。
- 适用范围：新建与改造库表、字段、索引、迁移脚本；以 MySQL 8.0 + InnoDB 为准。
- 单一事实来源：一个概念只有一张主表、一个字段名，不重复定义。
- 精度优先：金额、费率、汇率一律 `decimal`，不用浮点存精确值。
- 显式优先：列一律 `NOT NULL` + `DEFAULT`，不留 NULL / 0 / 1 三态。
- 可演进：结构变更必须向后兼容、可回滚、可在线执行。
- 边界清晰：一张表只服务一个聚合根，跨表一致性由应用层保证。
- 偏离须声明：任一条无法满足，须写明原因、风险与补救计划。

## 二、命名规范

- 全小写、下划线分词；禁大写、驼峰、中文、空格、连字符。
- 表用单数名词，不加 `t_` / `tbl_` 前缀，如 `order_item`。
- 主键列一律 `id`，不用 `order_item_id`。
- 外键列用 `<被关联表名>_id`，如 `order_id`。
- 布尔列 `is_` / `has_` / `can_` 前缀；时间列时点用 `_at`、日期用 `_on`。
- 索引名 `idx_` / `uk_` / `fk_` + 列名，≤64 字符。
- 禁用保留字：`order`、`desc`、`key`、`group`、`range`、`condition`。
- 禁拼音；缩写仅限 `id`、`url`、`ip`、`sku`、`spu`、`api`、`qty`。
- 主子表 `<主表>_<子>`；中间表按字母序（`role_user`）；扩展表 `<表>_ext`。

## 三、表与字段设计

- 必备四列：`id`、`created_at`、`updated_at`、`deleted_at`。
- 引擎 `InnoDB`，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`；禁 `utf8`。
- 每张表、每个字段必须有 `COMMENT`，写业务含义。
- 单表 ≤30 列、`varchar` 合计 ≤8000 字节、索引 ≤5 个；超出拆 `<表>_ext`。
- 主键 `bigint unsigned`，自增或雪花 ID。
- 金额 `decimal(18,2)`；禁 `float` / `double`。
- 时间 `datetime(3)` 统一存 UTC；禁 `timestamp`、禁字符串存时间。
- 布尔 `tinyint(1)`；状态 `tinyint` 且注释列全取值；禁 `enum` / `set`。
- 短文本 `varchar(n)` 按业务上限定长；禁 `varchar(255)` 兜底。
- `json` 只存不参与检索的字段；凡进 WHERE / GROUP BY 的必须拆列。
- 敏感字段加密存储 + HMAC 摘要列；密码只存 bcrypt / argon2id。
- 索引列序：等值 → 范围 → 排序；区分度 <0.05 的列不单独建索引。
- 索引列禁套函数、禁隐式类型转换（`where id='123'`）；禁左模糊 `like '%x'`。
- 建索引前查 `information_schema.STATISTICS`，禁止前缀可复用的冗余索引。
- 每个线上查询必须命中索引，`EXPLAIN` 不得出现 `type=ALL`。
- 设计必须给出预估行数、增长率、分片键；3 年内超 2000 万行须同时给分片方案。
- 聚合与统计走从库或离线链路，不在主库跑预计超 1s 的查询。
- 变更走版本化迁移并附 down 脚本，命名 `V<yyyymmddHHMMSS>__<动词>_<对象>.sql`。
- 大表（>500 万行或 >20 GB）加索引、改结构用 `gh-ost` / `pt-osc`，禁直接 `ALTER`。
- 加列用 `ALGORITHM=INSTANT` 且追加在末尾，禁在已有列中间插入。
- 删列、改类型走三阶段：新增兼容列双写 → 回填校验 → 停读后删旧列。
- 上线顺序：向后兼容的 DDL → 应用代码 → 清理；回滚时旧代码须可用。

## 四、主键、外键与完整性约束

- 每张表必须有单列代理主键，禁无主键表。
- 禁业务字段或业务联合键作主键，业务唯一性交给唯一索引。
- 禁字符串、随机 UUID 作主键（页分裂、索引膨胀）；对外 ID 另设 `uuid` 唯一列。
- 禁生产库建物理外键；关联完整性由应用层 + 对账任务保证。
- 关联列类型须与被引用表主键完全一致，且必须建索引。
- 唯一性由唯一索引保证，禁应用层"先查后插"。
- 逻辑删除统一用 `deleted_at`，零值表示未删除；禁 `is_deleted`、禁用 NULL。
- 软删表的唯一键必须包含 `deleted_at`，否则软删后无法重建同键记录。
- 有界取值用 `tinyint` + 应用层常量表 + 注释列全枚举；禁 `enum` / `set` / 触发器。
- 低频约束可用 `CHECK`（8.0.16+），高频写表只在应用层校验。
- 事务只包数据库操作，禁内嵌 RPC / HTTP / 文件 IO；单事务 ≤3s。
- 多行加锁按主键升序，避免交叉死锁；死锁（1213）幂等重试一次。
- 并发覆盖用乐观锁 `version`：`update ... where id=? and version=?`，影响 0 行则重读。
