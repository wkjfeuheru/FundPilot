# TA 回执确认实施记录

## 范围与计划（2026-11-17）

依据 CLAUDE.md、设计 01 F-D-01～07 / BR-34～39 / DF-13～16、02 AD-06/10、03 交易与 outbox 表、04 TA-01～05 / HOLDING-01 / TRADE-10 / PLATFORM-01、05 一致性评审。

1. 先补 MySQL/Redis 集成测试：成功与失败回执、T 日净值和 T+1 日期、账户范围、开关、重复回执、并发申购/回执、整单回滚、批量部分失败、建议状态同步。
2. 单笔回执与申购共用现金账户行锁；订单锁与状态条件兜底。现金、持仓、明细、订单、回执、审计和终态 outbox 同事务。按份额比例冲减赎回成本，清仓保留零份额行；调仓按设计净额结算。
3. 批量请求先固化目标订单并防重，逐单独立事务，最终缓存汇总；中断或缓存丢失时同键拒绝再执行，不自动扩大目标或重复结算。正常重试回放首次结果。
4. outbox 经数据库租约调度，建议订阅者幂等推进 CONFIRMED → COMPLETED / TA_FAILED；消费与派发标记同事务。未实现的建议发起页面不在本次扩大开发。
5. 独立 TA 页面：账户指标、待登记队列、服务端回执预览、逐笔成功/失败、批量二次确认、部分失败结果、最近回执。新增只读预览接口补齐原型弹窗字段，计算仍完全在服务端。
6. 用户交易/持仓页自动刷新已确认结果，增加持仓只读接口与页面、业务日期接口、投顾归属范围内的只读交易接口；不扩大实现完整资产总览、赎回发起和投顾组合管理页面。
7. 完成前后端全量测试、三端构建、独立代码复核、真实浏览器验收和演示数据/资金核对，记录结果。

TA 默认关闭；明确配置 `TA_ENABLED=true` 与固定 `TA_DEMO_USER_ID` 后才开放演示。用户端没有写回执按钮，匿名 TA 演示工具不新增账户体系。

## 已完成实现

- TA-01～05：指标、分页待登记队列、逐笔成功/失败、批量独立提交和最近回执；TA-06 补充服务端只读预览（含确认编号、T/T+1 日期、净值、金额、份额和费用），已同步 API 设计。
- 申购/定投按净金额增加份额与成本；赎回按申请份额、调仓卖出按申请金额与 T 日净值结算。持仓不足、资金不足、净值缺失时不进行半笔结算；失败回执只释放冻结。
- 申购与回执先取得同一资金账户行锁。订单、现金、持仓、成交明细、回执、审计、终态事件和幂等记录同事务；整单失败会回滚。历史 `freeze_amount` 保留申请值，当前冻结由 `PENDING_TA` 订单求和。
- 批量开始时保存目标订单及审计，每笔独立事务；部分失败返回具体订单与错误。正常重试回放首次汇总（全部成功缓存 7 天、部分失败 5 分钟）。无法恢复首次结果时拒绝同键重做，界面要求核对后明确结束旧操作。
- outbox 默认每 5 秒通过数据库租约派发终态事件；建议订阅者按订单归属及终态更新 `COMPLETED` / `TA_FAILED`，重复事件不重复推进版本。失败事件 30 秒后重试，计数饱和于 127，避免数据库 TINYINT 溢出阻塞其他事件。
- 用户持仓列表、交易记录、资产总览在返回页面及可见时每 30 秒刷新；持仓复用资产模块快照和金额计算。新增当前业务日期和投顾客户交易只读接口，客户归属校验保持有效。
- 未新增数据库表、迁移或外部依赖；没有实现真实 TA 通道、赎回发起或完整调仓建议发起页面。

## 验收证据（2026-11-17）

前端 `npm test -- --run`：14 个测试文件、66 项通过；`npm run build`：TypeScript 与三端构建通过。新增 TA 交互 4 项、持仓刷新 1 项。日志为 `frontend/ta-final-tests.log`、`frontend/ta-final-build.log`。

为避免同时运行的另一项验收覆盖 Maven 输出，仅将原 POM 的构建目录分别改为 `target-ta` / `target-ta-check` 的临时副本；依赖、测试源、测试规则不变。日志：`web-ai-tougu/ta-final-verify.log`、`ta-final-targeted.log`、`ta-concurrency-final.log`。日常复现直接在 `web-ai-tougu` 执行 `mvn verify` 或 `mvn '-Dit.test=AuthIT,TaReceiptIT,PurchaseIT' verify`。
