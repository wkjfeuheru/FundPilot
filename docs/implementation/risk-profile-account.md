# 用户端风险画像与账户实施与验收

日期：2026-11-16。依据：CLAUDE.md、docs/design 全部五份设计文档；范围 F-U-601～603、UC-U-12、AUTH-04、USER-01～03。

## 实施计划

1. 先编写 MySQL/Redis Testcontainers 接口集成测试和页面行为测试，确认新增功能测试失败。
2. 实现版本化问卷读取、服务端评分与可配置等级边界、上海业务日期有效期；首次创建画像，重测只更新测评字段。问卷选项分值不下发客户端。
3. 将测评记录、画像、审计、数据库幂等记录放在同一事务，提交后缓存响应；重复提交回放，缓存缺失时拒绝重复写。用用户行锁串行化同用户测评。
4. 实现画像和只读账户资料、问卷完整性校验、提交等待与错误重试、结果回显及认证/基金风险展示刷新；保留缺失、过期、加载失败状态。
5. 增量 SQL 提供标注为演示的问卷，不改既有 schema.sql，不修改原有账户和基金数据。
6. 执行后端 mvn verify、前端测试和构建、真实浏览器桌面/移动端验收，记录结果及边界。

## 口径与边界

- 新账户无画像，显示“未测评”；静态 KYC 缺失显示“待完善”，不虚构账户类型或投资期限，不开放编辑。
- 过期仅提示重测，保留上次结果；有效期截止日当天仍有效。
- 总分按问卷最高可能分值五等分，边界归较低等级；可通过配置覆盖分数上界。
- 本期使用独立版本演示问卷，不能视作机构已审核的正式适当性问卷。
- 沿用现有成功响应 code=0；本次不改变全站成功响应封装。
- 实施期间工作区存在并行申购模块改动。本任务负责画像数据与基金超市提示同步，不将其他模块的交易实现计入本任务交付。

## 运行与配置

1. 先按原认证模块说明连接目标 MySQL 库；人工执行 `scripts/sql/V001__demo_risk_questionnaire.sql`。脚本不含 `USE`，必须明确指定目标数据库，不会由应用自动执行。
2. 正常入口仍为用户端 `http://localhost:5173/investor/profile`，API 代理默认 8080；后端需要重新启动以加载本次新增接口。
3. 本次为避免影响并行开发，额外保留 `http://localhost:5176/investor/profile` → 18080 的验收预览。该端后端使用独立 JAR 副本 `web-ai-tougu/target/risk-preview/risk-preview.jar`，前端临时配置 `frontend/output/risk-vite.config.mjs`。这些不是部署产物。原 5173/5174/5175 开发服务已恢复。
4. `app.risk-assessment.validity-months=12`；`levels: []` 按最高可能总分五等分，演示问卷最高 160 分，对应含端点上界 32/64/96/128/160。可显式配置五个严格递增的非负整数上界，最后一项必须覆盖问卷最高分。
5. Redis 响应缓存保留 7 天；缓存不可用仍可提交首次测评，重复请求不会重复落库，返回冲突并提示核对结果。应用每 10 分钟清理本接口到期幂等记录，每批 1000 条；测评和审计历史不删改。
