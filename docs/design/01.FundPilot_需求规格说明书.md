### 1.2 编写目的

本文档基于 `docs/prototype` 目录下的三端界面原型（用户端 Investor、FA 端 Advisor、TA 演示端 Demo），全面提取并梳理需要开发的业务功能点，形成结构完整、无歧义的需求基线，用于：

1. **开发依据**：指导前后端开发人员进行系统设计与编码实现；
2. **测试依据**：为测试团队提供用例设计、场景覆盖的输入；
3. **验收依据**：作为产品、业务方与客户进行阶段验收与最终验收的标准；
4. **变更基线**：后续需求变更须基于本文档进行版本化管理与差异追溯。

### 1.3 适用范围

**适用读者**：产品经理、项目经理、系统架构师、前端/后端/AI 工程师、测试工程师、UI 设计师、合规风控人员、运维工程师。

**适用系统**：FundPilot 用户端（C 端投资者）、FA 端（FundPilot PRO 投顾工作台，B 端投资顾问），以及支撑两端业务的 AI 能力服务层；另含 TA 演示端（`ta/ta-simulator.html`），仅用于演示与测试第三方登记确认，不属产品功能。

**不适用范围**：基金公司内部 TA 过账系统、证监会监管报送系统、真实资金结算渠道对接系统。

### 1.4 术语定义

| 术语 | 定义 |
|---|---|
| **投顾 / Advisor** | 持牌投资顾问角色，负责客户服务、组合管理、报告生成与方案审批 |
| **FA 端** | Financial Advisor 端，即 FundPilot PRO 投顾工作台（原"投顾端"），面向投资顾问的产品端；入口页以"FA端 · 投顾工作台"卡片呈现 |
| **TA 端** | 演示端，指 TA 回执模拟台 `ta/ta-simulator.html`；入口页以"TA端 · 登记确认"卡片呈现，明确标注"演示端 · 非产品功能" |
| **C 端用户 / Investor** | 使用用户端的个人投资者，如原型中的"陈女士 · 平衡型投资者 / R3" |
| **AUM** | Assets Under Management，管理资产规模（投顾个人口径或平台口径） |
| **风险画像 / 风险等级** | 依据适当性测评得出的投资者风险承受能力分级，取值 R1–R5（保守/稳健/平衡/成长/进取） |
| **适当性匹配** | 将产品风险等级与投资者风险承受能力进行合规校验的过程 |
| **模型组合** | 由量化引擎维护的标准化资产配置组合（如"稳健增值 03 号"），含目标权重 |
| **配置漂移 / 偏离** | 实际持仓权重相对目标权重的差异程度 |
| **再平衡** | 将组合权重从偏离状态调回目标配置的操作，原型中需人工审批 |
| **AI Copilot** | 双端内嵌的 AI 助手（用户端"AI 理财助手"/投顾端"投顾 Copilot"），提供解释、诊断与草案生成 |
| **草案（Draft）** | AI 生成的建议、方案或报告初稿，不具备直接生效能力，必须经人工复核 |
| **留痕** | 关键业务操作（复核、审批、执行）写入可追溯审计日志的行为 |
| **模拟/演示数据** | 原型中的基金净值、收益率、客户数据均为虚构，不构成投资建议 |
| **自选基金** | 用户在基金超市中标记关注的基金列表 |
| **定投计划** | 按固定周期（如每月 8 日）与固定金额自动申购基金的预约安排 |
| **策略库** | 经系统化评价、评级与合规审核后上架的标准化投资策略集合；按风险等级与投资目标分类，是客户配置的起点 |
| **KYC** | Know Your Customer，客户画像与适当性信息集合：风险等级、投资目标、投资期限、流动性需求、投资经验等 |
| **KYC 匹配** | 以风险等级、期限、流动性、起投金额等硬约束过滤策略，再按目标契合度、回撤、夏普、稳定性等加权评分排序 |
| **SAA（战略资产配置）** | 基于长期资本市场假设与客户目标确定的大类资产基准权重及允许区间带，是组合的长期锚 |
| **TAA（战术资产配置）** | 在 SAA 区间带内，根据阶段性市场判断对大类资产做超低配的战术偏离，受偏离阈值与跟踪误差约束 |
| **基金池** | 经准入筛选的公募基金集合，含类型、风格、费率、规模、流动性、评级等标签，是组合构建的标的来源 |
| **组合三层对象** | 策略（Strategy）→ 模型组合（ModelPortfolio）→ 客户组合（ClientPortfolio）三级引用关系 |
| **调仓建议（Rebalance Advice）** | 投顾基于客户画像、组合偏离与基金池检视结果生成、推送给客户的调仓方案；含调出/调入基金、仓位变化、金额、费用与有效期 |
| **跟调** | 客户核对调仓建议后点击"确认跟调"，系统据此创建调仓交易；不操作则持仓保持不变 |
| **在途交易** | 已提交但尚未经 TA 确认的申购/赎回/调仓交易；在途期间暂停跟调，避免资金重复占用 |
| **交易两阶段** | 提交申请 → 待登记确认 → 模拟 TA 回执 → 确认成功/确认失败；持仓与现金仅在确认成功后更新 |
| **TA（基金注册登记机构）** | 第三方登记机构，负责确认申购份额、赎回金额与登记结果；原型以「模拟 TA 回执」逐笔模拟 |
| **TA 回执** | TA 返回的确认结果：确认编号、确认日期、确认净值、确认份额/金额、手续费、成功/失败与失败原因 |
| **现金账户** | 用户可用于申购的资金账户；可用现金 = 现金余额 − 待登记申购冻结金额 |
| **确认失败** | TA 因基金交易状态限制（暂停申购/限购/暂停赎回/赎回受限）拒绝确认；持仓与现金保持不变 |
| **TA 回执模拟台** | 原型演示工具（非产品功能）`ta/ta-simulator.html`，用于逐笔/批量模拟第三方 TA 回执；客户与投顾均通过只读页面查看结果 |

## 2. 项目概述

### 2.1 项目背景

个人投资者在基金投资中普遍面临三类痛点：**看不懂**（净值、回撤、波动率、风险等级等专业概念理解门槛高）、**配不好**（大类资产比例失衡、单只基金集中度过高、缺乏与自身风险承受能力匹配的配置方法）、**管不住**（缺少持续的组合跟踪与偏离预警，调仓决策缺乏依据）。

对投资顾问而言，服务大量客户时存在效率瓶颈：客户画像分散、组合健康检查依赖人工、报告撰写耗时、风险事项响应滞后，且 AI 建议的合规审批缺少系统化管控链路。

FundPilot 旨在构建"**AI 辅助 + 人工管控**"的基金投顾平台（用户端 + FA 端两个产品端，另设 TA 演示端）：C 端用户获得可解释的配置与持仓洞察，FA 端投顾获得客户 360、策略优化、风险监控与报告生成的效率工具；所有 AI 输出均为"草案"，关键操作必须经过规则校验、人工复核与合规审批。

### 2.2 建设目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 为 C 端用户提供资产总览、基金超市与申购、投顾调仓建议、持仓与赎回、交易记录、风险画像与 AI 理财助手的一站式财富管理界面 | 7 个导航模块全部上线（原型第 5 章功能清单） |
| G2 | 为投顾提供客户 360、策略库、三级组合管理、风险监控、报告中心、审批合规的完整工作台 | 8 大功能模块全部上线（原型第 6 章功能清单） |
| G3 | 在双端嵌入 AI Copilot，覆盖组合诊断、配置解释、基金筛选、报告起草等场景 | 7.1 节场景清单全部可调用 |
| G4 | 建立"AI 生成 → 规则校验 → 人工复核 → 合规审批 → 留痕执行"的可审计管控链路 | 审批链路 5 节点全部实现且操作可追溯 |
| G5 | 将风险预警（超限、集中度、配置漂移、回撤）从被动发现转变为规则引擎主动识别 | 风险事件自动生成并进入处置队列 |

### 2.3 核心价值

1. **对 C 端用户**：随时理解"我的钱配在了哪里、为什么这样配、风险在哪里"；AI 用自然语言解释专业概念，配置方案可解释、可对比、不自动执行。
2. **对投顾**：客户数据聚合呈现（客户 360）、AI 预筛重点事项（今日简报、优先级排序）、报告初稿自动生成，显著降低单客户服务成本。
3. **对平台/合规方**：所有 AI 建议与投顾操作形成"生成—校验—复核—审批—留痕"的完整证据链，满足适当性与可审计要求。
4. **风险前置**：KYC 适配、SAA 区间越界、TAA 偏离、集中度/流动性、回撤与策略健康等由规则引擎自动识别并推送处置。

### 2.5 实施范围边界

**范围内（In Scope）**

1. 用户端 7 个导航模块 + 全局框架（侧边栏、顶栏、通知、AI 悬浮入口、抽屉）；
2. FA 端（FundPilot PRO）8 个导航模块 + 全局框架（同上，另含风险红点计数）；
3. 两端 AI 对话抽屉与 AI 独立页（快捷提示词、上下文感知、预设回复逻辑）；
4. 规则引擎产生的风险告警及其"标记已复核"处置流；
5. 报告生成流程（模板选择 → 生成草案 → 进度跟踪 → 预览）；
6. 审批队列与审批链路状态机；
7. 原型入口页三端并列（用户端 / FA 端 / TA 端）与 TA 演示端单页（非产品功能，仅演示登记确认）；
8. 注册与开户：投资者/投顾自助注册；投资者开户赠送演示现金 ¥50,000；投顾账号权限由机构分配（本期无分配入口）。

**范围外（Out of Scope）**

1. **真实交易通道**：申购、赎回、定投均通过"模拟申购草案/模拟交易"呈现，不连接真实基金销售渠道与资金结算（原型 role-banner 明示）；
2. **真实行情与净值数据**：净值、收益率、波动率均为模拟数据；
3. **真实支付与账户开立**：不涉及银行卡绑定、资金划转；
4. **监管报送**：不包含向监管机构的数据报送接口；
5. **AI 实时模型推理**：原型为预设回复，生产实现时按第 7 章要求接入，但 AI 输出始终不直接触达交易。

### 3.3 核心业务流转主链路

**主链路一：C 端配置与跟调链路（投顾推送 + 用户确认）**

```
查看资产总览 → 收到投顾调仓建议通知 → 进入「调仓建议」
   → 核对调出/调入基金、仓位变化、金额与费用
   → 确认跟调 / 暂不跟调（不操作则持仓保持不变）
   → 确认跟调后创建调仓交易（待登记确认）并报送 TA
   → 演示工具「TA 回执模拟台」逐笔/批量提交回执（客户侧只读）
   → 确认成功：持仓与现金更新；确认失败：保持原状
```

**主链路一补充：C 端自主交易链路（含 TA 确认）**

```
基金超市/基金详情 → 申购（校验可用现金；金额、费率、适当性）→ 待登记确认
我的持仓 → 赎回（校验可赎回份额；按份额/全部赎回）→ 待登记确认
演示工具「TA 回执模拟台」→ T+1 确认，按 T 日净值提交回执
   → 客户在交易记录只读查看确认成功/失败与回执详情
   → 确认成功：申购扣减现金并增加持仓；赎回减少持仓并增加现金
   → 确认失败（基金暂停申购/限购/暂停赎回/赎回受限）：持仓与现金不变
```

**主链路二：投顾客户服务链路（AI 辅助 + 审批管控）**

```
工作台 AI 简报/风险告警 → 客户 360 查看画像与洞察
   → AI 诊断客户组合 → 策略库按 KYC 匹配策略并生成 SAA/TAA 草案（约束校验）
   → 生成客户配置建议书（报告中心）
   → 投顾人工复核 → 合规审批与客户确认 → 留痕与执行
```

**主链路三：风险处置链路**

```
规则引擎扫描（46 条预设规则：KYC/适当性、SAA 区间、TAA 偏离、集中度、流动性、回撤与策略健康）→ 生成风险事件（高/中/低）
   → 风险监控台列表 + 侧边栏红点 → 投顾人工复核（标记已复核）
   → 必要时进入合规审批流程 → 处置留痕
```

> 三条链路共同体现核心管控原则：**AI 可生成建议，不得自动修改风险阈值、不得跳过审批、不得自动下单**。

### 7.2 输入输出要求

**输入（用户侧）**

| 项 | 要求 |
|---|---|
| 提问形式 | 自然语言文本，单条最长 300 字符 |
| 上下文来源 | ①当前页面/工作区状态（所在模块、选中策略/组合/客户）②客户 KYC（风险等级、期限、流动性、目标）③SAA/TAA 与基金层持仓（系统注入，非用户手输）④客户 360 场景下的客户档案 |
| 预置 prompt | 每个能力场景配置固定预置 prompt（见第 5、6 章各功能点），由系统代填代发，用户可感知内容 |

**输出（AI 侧）**

| 项 | 要求 |
|---|---|
| 形式 | 对话气泡内纯文本，保留换行结构；不得输出可执行交易指令 |
| 结构 | 场景化标题（如【客户组合诊断】）+ 编号要点 + 明确的"下一步"指引 |
| 数据引用 | 必须标注数据为模拟/演示口径；引用具体指标时给出数值与来源说明 |
| 合规要素 | 含免责/边界提示；投顾侧输出必须包含"草案待复核、需规则校验与审批"的流程提示 |
| 状态 | AI 输出一律为草案（Draft），不直接改变任何业务对象状态 |

### 7.3 调用逻辑

**关键词路由（原型已实现的确定性行为；生产版作为 LLM 服务不可用时的降级兜底链路，兜底回复同步告知"当前为简化模式"）**

用户端关键词路由（按优先级）：

| 优先级 | 匹配关键词 | 回复模板 |
|---|---|---|
| 1 | 调仓/跟调/建议/调出/调入 | 调仓建议解读：调出/调入基金、仓位变化、跟调流程（不确认不执行、交易确认后持仓才更新） |

| 4 | 债券/筛选/基金 | 基金筛选思路：先定类型再核费率/久期/回撤/团队/流动性 |
| 5 | 定投 | 定投知识：纪律作用 + 不能消除风险 + 前置条件 |
| 6 | 配置/解释/权重 | 配置逻辑：四大类作用 + 示例比例说明 + 正式流程提示 |
| 兜底 | 其余 | 通用回复：能力范围说明 + 引导提问 |

投顾端关键词路由：

| 优先级 | 匹配关键词 | 回复模板 |
|---|---|---|
| 1 | SAA/TAA/战略/战术/偏离 | 双层配置解释：SAA 基准与区间带、TAA 偏离示例、阈值与基金层约束（单基金≤25%、单管理人≤35%） |
| 2 | 陈悦/客户组合/诊断 | 客户组合诊断：KYC 与策略风险等级不匹配 + SAA 区间内偏离 + 策略重匹配与审批流程 |
| 3 | 今日/风险/告警/待办 | 今日简报：客户数/6 项风险/7 份待审 + 三项优先级（KYC 适配、SAA 越界、TAA 偏离）+ 留痕要求 |
| 4 | 策略/匹配/优化/配置 | 策略匹配与双层配置：KYC 硬约束+加权评分、SAA/TAA、基金池构建约束 |
| 5 | 报告/沟通/提纲 | 报告草案提纲：目标与适当性、策略与配置框架、组合表现、风险分析、建议与审批记录 |
| 兜底 | 其余 | 通用回复：五步拆解方法论（画像→校验→计算→规则→解释） |

**调用链路（生产方案已确认：LLM + 工具调用，2026-11-15 对齐，见 12.2 TODO-05）**

生产实现采用 **LangGraph 编排 + DeepSeek 推理**：意图识别与回复生成由 LLM 完成，量化指标计算、组合诊断、约束校验封装为可复用工具节点；LLM 服务异常或超时（>10s）时降级到下方关键词路由兜底。预置 prompt 场景（7.1）保留为固定入口，仅改变生成方式、不改变触发交互。

```
用户提问/预置 prompt
  → 意图识别（LLM）
  → 上下文组装（客户 KYC + 策略/SAA/TAA + 基金持仓 + 工作区状态）
  → 工具调用（策略匹配评分、SAA/TAA 校验、组合诊断、集中度校验）
  → 生成回复（附数据来源与免责）
  → 前端渲染（保留换行）
  → 对话记录留痕（4.9）
```

**边界约束（必须实现，双端一致）**

1. AI 不得输出直接执行的调仓、申购、赎回指令；
2. AI 不得修改风险阈值、规则配置；
3. 投顾侧 AI 产物（方案、报告）进入审批链路（BR-07），审批权在人；
4. 用户端 AI 不得替代适当性测评与确定性规则校验。

### 8.2 计算规则

| 编号 | 计算项 | 规则 | 备注 |
|---|---|---|---|
| CR-01 | 持有占比 | 单基金持有市值 / 总资产 × 100%，保留 1 位小数 | 持仓表 |
| CR-02 | 累计收益 | 持仓市值 − 持仓成本；收益率 = 收益/成本 | 正绿负红 |
| CR-03 | 配置偏离 | |实际大类权重 − 目标权重|，取最大单项作为组合偏离度 | 组合管理/风险告警 |
| CR-04 | 区间收益 | 选定区间（1M/3M/6M/1Y）组合累计收益率 | 趋势图联动 |
| CR-05 | 风险测评覆盖率 | 已完成有效测评客户数 / 在管客户数（示例 98.6%，286 人中需补全 4 人） | 投顾指标卡 |
| CR-06 | 待处理告警数 | Σ(风险事件.处置状态=未复核)，按级别可再统计高优先级 | 动态指标 |
| CR-07 | KYC 匹配度 | 目标契合×30% + 回撤评分×20% + 夏普评分×15% + 稳定性×15% + 收益×10% + 费率×10%，四舍五入取整（0–100） | 策略匹配 |
| CR-08 | SAA 偏离 | max(\|实际权重 − SAA 基准\|)，四类资产取最大值（pp） | 模型/客户组合 |
| CR-09 | TAA 偏离 | max(\|TAA 权重 − SAA 基准\|)，并单独标注每类偏离 pp | F-A-313/F-A-405 |
| CR-10 | 集中度 | 单基金权重 = 基金市值/组合市值；单管理人 = Σ同管理人基金权重；行业 = 穿透后行业权重合计 | 基金层构建与风险 |
| CR-11 | 策略综合分 | 7 维评分加权汇总为 0–100，并映射 1–5 星；评级下调触发策略健康告警 | 策略库 |
| CR-12 | 申购份额与费用 | 申购费 = 申购金额 × 申购费率；预计份额 = (申购金额 − 申购费) / 模拟净值 | 申购弹窗 |
| CR-13 | 赎回金额与费用 | 赎回总额 = 赎回份额 × 模拟净值；赎回费 = 赎回总额 × 赎回费率；预计到账 = 赎回总额 − 赎回费 | 赎回弹窗 |
| CR-14 | 调仓金额 | 单基金调仓金额 = (目标仓位 − 当前仓位) × 组合市值；调出为负、调入为正；汇总调出/调入金额与换手率 | F-U-303/304 |
| CR-15 | TA 确认份额/金额 | 申购确认份额 = (申购金额 − 申购费) ÷ T 日净值；赎回确认金额 = 赎回份额 × T 日净值；赎回到账 = 确认金额 − 赎回费 | 申购/赎回弹窗与 TA 回执 |
| CR-16 | 可用现金 | 可用现金 = 现金余额 − Σ待登记申购金额；确认成功后释放冻结并扣减现金 | F-U-506/资金账户 |

### 8.3 异常处理规则

| 编号 | 异常场景 | 处理方式 |
|---|---|---|
| ER-01 | 基金搜索无结果 | 展示空状态"没有找到匹配的基金产品"，保留筛选条件 |
| ER-02 | 客户搜索无结果 | 展示空状态"没有匹配的客户" |
| ER-03 | 风险事件全部复核完毕 | 列表展示空状态"当前没有待处理的模拟风险告警 ✓"，红点隐藏 |
| ER-04 | 重复审批 | 按钮 disabled 拦截（BR-08），不产生二次状态变更 |
| ER-05 | 输入为空/纯空白 | AI 对话不发送消息，输入框保持聚焦 |
| ER-06 | AI 无法识别意图 | 兜底模板回复（能力说明 + 引导），不得虚构数据 |
| ER-07 | 报告未生成时预览 | 展示"模板预览"状态，不出现"AI 草案"字样 |
| ER-08 | 越权操作 | 客户数据仅限本投顾名下（生产要求，原型以演示账号呈现） |
| ER-09 | 无通过硬约束的策略 | 候选区展示空状态"没有通过硬约束的策略，请调整客户 KYC 或策略库"，不强行推荐低匹配策略 |
| ER-10 | TAA 调整越界 | 提示"该大类权重需保持在 X%–Y% 区间内"，本次调整不生效，权重保持不变 |
| ER-11 | 策略/客户切换 | 已生成的报告与配置草案作废，回到"模板预览"或重新匹配状态，避免脏状态残留 |
| ER-12 | 无待确认调仓建议 | 展示空状态"当前没有待确认的调仓建议"，持仓保持不变，提供查看持仓与联系投顾入口 |
| ER-13 | 调仓建议过期 | 状态标记"已过期"，确认按钮不可用，建议转入历史；持仓不变 |
| ER-14 | 赎回份额超限 | 提示"赎回份额不能超过可赎回份额"，本次提交不生效 |
| ER-15 | TA 确认失败 | 交易标记"确认失败"并展示失败原因（基金暂停申购/限购/暂停赎回/赎回受限）；持仓与现金保持原状，可在交易记录查看回执 |
| ER-16 | 可用现金不足 | 申购提示"可用现金不足：当前可用 ¥X（含冻结待登记申购）"，本次提交不生效 |
| ER-17 | 无待登记交易 | TA 回执按钮仅对待登记确认交易展示；已确认成功/失败交易仅展示回执详情 |

### 9.3 数据流转规则

| 编号 | 流转 | 规则 |
|---|---|---|
| DF-01 | 持仓 → 资产总览 | 持仓按市值降序取 Top3 展示；全量展示于持仓页；汇总指标由持仓聚合计算 |
| DF-02 | KYC + 策略库 → 候选策略 | 按 KYC 硬约束过滤策略，再按 BR-06 评分排序，输出候选与匹配理由 |
| DF-03 | RiskEvent → 红点/指标 | 未复核事件数实时驱动侧边栏红点、待处理告警指标卡、通知文案 |
| DF-04 | SAA/TAA/基金层 → 审批 | 策略选定后生成的 SAA/TAA 草案与基金调仓草案分别进入 ApprovalItem 队列（层级 SAA/TAA/基金） |
| DF-05 | Report → 审批 | 报告生成即创建待复核状态；预览状态为 TEMPLATE_PREVIEW 时不可对外 |
| DF-06 | ApprovalItem → AuditLog | 复核通过动作写入审计日志（动作、对象、层级、时间、操作人） |
| DF-07 | 页面交互 → Chat | 全部预置 prompt 按钮统一经由"打开抽屉 + 自动发送"链路，消息带上下文快照 |
| DF-08 | 导航状态 | 当前页面经独立 HTML 路径持久化；策略库支持 `?tab=config`、`?client=` 深链恢复页面与上下文 |
| DF-09 | 策略 → 模型组合 → 客户组合 | 策略上架后生成模型组合；客户组合引用模型组合并继承 SAA/TAA 框架，实际权重可漂移 |
| DF-10 | 风险分类 → 筛选 | 风险事件分类字段驱动风险页分类筛选、指标统计与处置流程 |
| DF-11 | 投顾推送 → 调仓建议 | 投顾在客户组合抽屉推送后生成 RebalanceAdvice（含明细、费用、有效期），客户端「调仓建议」页读取并展示；未确认不产生交易 |
| DF-12 | 确认跟调 → 交易委托 | 客户确认跟调后建议状态置 CONFIRMED，并生成调仓 TradeOrder（待登记确认、报送 TA）；暂不跟调置 REJECTED，不生成交易 |
| DF-13 | TA 回执 → 持仓/现金 | 模拟 TA 回执确认成功后 TradeOrder 置 CONFIRMED，按 effect 更新持仓与现金（申购扣现金/加持仓、赎回减持仓/加现金、调仓按明细增减并扣费）；确认失败置 FAILED，不变更 |
| DF-14 | 在途交易 → 跟调互斥 | 存在 PENDING_TA 交易时，调仓建议确认按钮禁用；TA 确认完成（成功或失败）后自动解除 |
| DF-15 | 申购冻结 → 可用现金 | 待登记申购金额计入冻结，可用现金 = 现金余额 − 冻结；TA 成功后释放冻结并扣减现金 |
| DF-16 | 客户交易 → 投顾只读 | 投顾端客户组合抽屉读取客户最近交易与 TA 状态，仅展示回执，不可代客户确认 |
