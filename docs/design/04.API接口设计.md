## 1. 文档说明

### 1.1 设计目标

1. 为需求第 5/6/7 章全部功能点提供可实现的 REST 契约，覆盖注册/认证、用户端 7 模块、FA 端 8 模块、TA 演示台与 AI 能力；
2. 统一成功/失败响应、分页、序列化、参数校验、异常处理、认证授权、幂等与审计口径，避免各模块各自为政；
3. 严格对齐库设计 41 张表与枚举取值，接口响应字段可追溯到具体表列；
4. 对齐架构 4.1 模块划分与 AD-03/AD-04/AD-05/AD-06/AD-09/AD-11 决策；
5. 为前端 `api/endpoints/*` 与后端 controller 提供一一对应的实现基线。

### 1.2 本阶段不做的事

- 不编写 Controller/Service/Mapper、不生成 DTO 代码；
- 不修改 `scripts/sql/schema.sql` 与库设计文档（四阶段本身不改库；05 评审阶段对脚本库名/注释的修订见《05.设计方案评审》，无表结构变更）；
- 不定义真实 TA/基金销售/支付通道接口（需求 2.5 范围外）；
- 不定义运营后台（策略上下架、规则阈值编辑）接口：需求 6.9 明确投顾无权限，DR-06 明确阈值编辑不在本期；
- 不定义 PDF 排版、AI 提示词内容与模型参数（分别属实现与 `web-ai-agent` 配置）。

## 2. 总体设计

### 2.1 设计原则

1. **资源化**：URL 用名词复数表达资源；状态推进用子资源（如 `/decisions`、`/reviews`、`/approvals`），避免动词路径；
2. **语义化**：GET 查询、POST 创建/推进、PUT 幂等创建或全量更新、PATCH 部分更新、DELETE 删除/取消；
3. **单一事实源**：金额、状态、权重等以库设计为准；禁止在接口层引入库中不存在且需持久化的字段；
4. **规则集中**：KYC 匹配、SAA/TAA 校验、集中度、金额计算统一由 `rule` 模块实现，Controller 不写业务规则（NFR-M4）；
5. **最小暴露**：Entity 不直接作为响应；所有响应使用 DTO/公共模型；敏感字段（`password_hash`）永不返回；
6. **可追溯**：所有关键写操作在响应中返回业务编号（`orderCode`/`adviceCode`/`reportCode`/`approvalCode`），并写审计。

### 2.2 URL 与 HTTP 方法规范

| 项 | 规范 |
|---|---|
| 前缀 | 所有业务接口以 `/api/v1` 开头；TA 模拟台为 `/api/v1/ta/*`；AI 内部工具为 `/api/v1/agent/tools/*` |
| 命名 | 资源名词复数、kebab-case（如 `rebalance-advices`、`trade-orders`、`risk-events`） |
| 当前用户 | C 端不写用户 ID；单例资源使用保留段 `/current`（如 `/asset-overviews/current`、`/cash-accounts/current`） |
| 投顾访问客户 | `/customers/{customerId}/trade-orders`、`/customers/{customerId}/strategy-matches`、`/customers/{customerId}/rebalance-advices`、`/customers/{customerId}/client-portfolios/current` 等；`{customerId}` 语义见 1.5 |
| 成功状态码 | 查询/更新返回 `200`；创建资源 `201`；异步受理 `202`；删除/取消 `204` |
| 时间 | 时点字段 `Instant`，ISO-8601 UTC（`2026-11-16T03:20:11.123Z`）；纯日期字段 `YYYY-MM-DD`（如 `tradeDate`、`navDate`、`validUntil`） |
| ID | JSON 中使用 number（int64）；路径变量为正整数 |
| 静态段优先 | 同一路径层同时存在静态段（`summary`/`current`/`active`）与 `{id}` 时，静态段优先；`{id}` 在实现层限定为 `\d+`，避免 `/customers/summary` 被 `{customerId}` 匹配 |
| 命名例外 | `GET /auth/me`（当前用户惯例）与 `POST /agent/chat`（架构 3.4 已指定路径）为明确例外，其余资源一律名词复数 |
| 不支持的资源操作 | 审计导出/删除、规则阈值编辑、策略上下架等不提供接口（404/405），文档中明确声明 |

### 2.3 统一成功响应

成功响应统一包裹 `ResponseDTO<T>`（`CLAUDE.md`）：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "id": 1024
  },
  "traceId": "9f2c1d7e8a4b4c6e",
  "timestamp": "2026-11-16T03:20:11.123Z"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 固定 `"OK"`；成功响应不使用数字码 |
| `message` | string | 固定 `"成功"`，前端不据此做逻辑判断 |
| `data` | object/array/null | 业务数据；删除类返回 `null`（HTTP 204 无 body） |
| `traceId` | string | 服务端生成的链路 ID，与 `audit_log.trace_id`、日志一致 |
| `timestamp` | Instant | 响应生成时间（UTC） |

> 文件下载（资产报告 PDF）不使用 `ResponseDTO` 包裹，直接返回 `application/pdf`（见 ASSET-03）。

### 2.4 分页响应

流水型列表统一返回 `PageResponse<T>`（`CLAUDE.md`）：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "items": [],
    "page": 1,
    "size": 20,
    "totalElements": 0,
    "totalPages": 0
  },
  "traceId": "9f2c1d7e8a4b4c6e",
  "timestamp": "2026-11-16T03:20:11.123Z"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `items` | array | 当前页数据 |
| `page` | int | 页码，**从 1 开始** |
| `size` | int | 每页条数，默认 20，最大 100 |
| `totalElements` | long | 总条数（`SELECT COUNT(*)` 与列表查询同条件） |
| `totalPages` | int | 总页数 = `ceil(totalElements / size)`；0 条时为 0 |

分页实现遵循 `CLAUDE.md`：MyBatis 手动 `LIMIT #{size} OFFSET #{(page-1)*size}`，不引入 PageHelper/Spring Data Page。

**不分页的主数据列表**：基金、策略、客户、模型组合、客户组合、定投基金选择列表、自选列表，直接返回 `items` 数组（或带 `summary` 的聚合对象），演示量级可控（基金 ≤50、策略 ≤10、客户 ≤300）。

### 2.5 序列化规则

| 数据类型 | API 表示 | 示例 | 说明 |
|---|---|---|---|
| 枚举 | 字符串常量 | `"PENDING_TA"` | 与库设计第 5 章枚举名称一致；映射见 3.1 |
| 金额 | 字符串，两位小数 | `"1286420.00"` | 对应 `decimal(18,2)`；前端 `Number()` 后格式化 |
| 份额 | 字符串，四位小数 | `"12000.4500"` | 对应 `decimal(18,4)` |
| 净值 | 字符串，四位小数 | `"2.1863"` | 对应 `decimal(11,4)` |
| 比率（夏普等） | 字符串，四位小数 | `"0.9200"` | 非百分数，按四位小数传输 |
| 权重/占比/收益率/费率 | 字符串，按库列精度 | `"38.0000"`、`"95.00"` | `decimal(7,4)`/`decimal(9,4)` 四位；`risk_rule.coverage_rate` 等 `decimal(5,2)` 两位；均为百分数值 |
| 计数/评分 | number | `86`、`286` | `int/smallint/tinyint` 计数、评分 |
| 布尔 | boolean | `true` | 对应 `tinyint(1)` |
| 时点 | ISO-8601 UTC | `"2026-11-16T03:20:11.123Z"` | 对应 `datetime(3)`，统一 UTC |
| 纯日期 | `YYYY-MM-DD` | `"2026-11-18"` | 对应 `date` |
| 空值 | `null` | `"adviceId": null` | 库中零值语义（0/epoch/空串）在 DTO 转换时映射为 `null`；**响应不使用 undefined/空字符串表示缺失** |
| JSON 数组列 | array | `styleTags: []` | 库中 JSON 列为 NULL 时返回 `[]`；对象型 JSON（如 `report.content`）无值时返回 `null` |
| JSON 字段 | object/array | `assetBefore` | 对应库中 `json` 列，按库设计结构原样返回 |

**零值到 null 的映射**（库设计 DDR-06/显式优先）：`advice_id=0` → `adviceId:null`；`plan_id=0` → `planId:null`；`generated_at=epoch` → `generatedAt:null`；`read_at=epoch` → `readAt:null`；`reviewed_at=epoch` → `reviewedAt:null`；`ended_at=epoch` → `endedAt:null`。

> **date 与 Instant 的边界**：库设计将业务日期（`trade_date`、`nav_date`、`valid_until`、`snapshot_date`、`cal_date`）定义为 `date`，本契约按 `YYYY-MM-DD` 传输；`datetime(3)` 时点（`created_at`、`pushed_at`、`evaluated_at` 等）一律按 `Instant` ISO-8601 UTC（`Z` 结尾）传输。此口径避免前端把"业务日期"按时区换算成前一天，属于对 `CLAUDE.md`"时间字段用 Instant"的**日期列适配说明**；**2026-11-16 评审确认（D-24）**。

### 2.6 错误响应

错误统一使用 Spring Boot 4 内置 `ProblemDetail`（RFC 7807，`CLAUDE.md`），**不使用 `ResponseDTO` 包裹**：

```json
{
  "type": "https://api.fundpilot.local/problems/business-rule-violation",
  "title": "业务规则校验失败",
  "status": 422,
  "detail": "可用现金不足：当前可用 45000.00 元（含冻结待登记申购）",
  "instance": "/api/v1/trade-orders/purchases",
  "code": "TRADE_AVAILABLE_CASH_INSUFFICIENT",
  "traceId": "9f2c1d7e8a4b4c6e",
  "timestamp": "2026-11-16T03:20:11.123Z",
  "errors": []
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | 问题类型 URI（按 HTTP 状态分类，固定几种） |
| `title` | string | HTTP 状态对应的中文标题 |
| `status` | int | HTTP 状态码 |
| `detail` | string | 面向用户的中文错误说明，可直接展示 |
| `instance` | string | 请求路径 |
| `code` | string | 业务错误码（大写下划线），前端据此做分支 |
| `traceId` | string | 链路 ID |
| `timestamp` | Instant | 错误时间 |
| `errors` | array | 仅参数校验错误时返回：`[{field, message, rejectedValue}]` |

`type` 取值固定为以下几类，便于前端按类别处理：

| `type` | HTTP | 含义 |
|---|---|---|
| `https://api.fundpilot.local/problems/validation-error` | 400 | 参数校验/请求格式错误 |
| `https://api.fundpilot.local/problems/authentication-error` | 401 | 未认证/会话过期/凭证错误 |
| `https://api.fundpilot.local/problems/authorization-error` | 403 | 角色、归属、CSRF 或账户状态不允许 |
| `https://api.fundpilot.local/problems/not-found` | 404 | 资源不存在（含演示功能关闭） |
| `https://api.fundpilot.local/problems/state-conflict` | 409 | 状态冲突、重复审批、幂等冲突 |
| `https://api.fundpilot.local/problems/business-rule-violation` | 422 | 业务规则不满足 |
| `https://api.fundpilot.local/problems/rate-limited` | 429 | 限流 |
| `https://api.fundpilot.local/problems/internal-error` | 500 | 服务端异常 |
| `https://api.fundpilot.local/problems/upstream-error` | 502 | AI 上游不可用 |

**HTTP 状态与错误码映射**

| HTTP | 使用场景 | 典型 code |
|---|---|---|
| 400 | 请求格式错误、字段校验失败、缺少/非法幂等键 | `COMMON_VALIDATION_FAILED`、`COMMON_MISSING_IDEMPOTENCY_KEY` |
| 401 | 未登录、会话过期、登录凭证错误 | `AUTH_UNAUTHENTICATED`、`AUTH_INVALID_CREDENTIALS` |
| 403 | 角色不符、越权访问名下客户、CSRF 失败、账户停用 | `COMMON_FORBIDDEN`、`CLIENT_NOT_ASSIGNED`、`AUTH_CSRF_INVALID` |
| 404 | 资源不存在，或演示功能已关闭 | `COMMON_RESOURCE_NOT_FOUND`、`TA_DISABLED` |
| 409 | 状态冲突、重复审批、幂等键冲突、用户名重复、不可编辑状态 | `COMMON_STATE_CONFLICT`、`APPROVAL_ALREADY_COMPLETED`、`AUTH_USERNAME_TAKEN` |
| 422 | 业务规则不满足（金额、份额、区间、适当性、匹配等） | `TRADE_AVAILABLE_CASH_INSUFFICIENT`、`STRATEGY_TAA_OUT_OF_RANGE` |
| 429 | 登录/关键接口限流 | `AUTH_LOGIN_RATE_LIMITED` |
| 500 | 未预期服务端异常 | `COMMON_INTERNAL_ERROR` |
| 502 | AI 服务不可用且降级链路失败 | `AGENT_SERVICE_UNAVAILABLE` |
| 503 | 认证限流依赖或数据库暂不可用 | `AUTH_SERVICE_UNAVAILABLE`、`DATABASE_UNAVAILABLE` |

> 业务规则失败统一用 422，而不是 400：400 只表示"请求本身不合法"（语法/类型/必填/格式），422 表示"请求合法但业务不允许"。前端可据此区分表单错误与业务提示。

### 2.7 参数校验

1. Controller 使用 `@Valid`/`@Validated` + Jakarta Validation 注解，**不在 Controller 写 if 判断**（`CLAUDE.md`）；
2. 校验失败由 `GlobalExceptionHandler` 统一转 `ProblemDetail(400, COMMON_VALIDATION_FAILED)`，`errors[]` 逐字段返回；
3. 公共约束：

| 参数类型 | 约束 |
|---|---|
| `page` | `@Min(1)`，默认 1 |
| `size` | `@Min(1) @Max(100)`，默认 20 |
| 路径 ID | `@Positive`，不存在返回 404 |
| 金额 | `@NotNull @DecimalMin("0.01") @Digits(integer=16, fraction=2)`；申购额外 `>= 100.00` |
| 份额 | `@NotNull @DecimalMin("0.0001") @Digits(integer=14, fraction=4)` |
| 权重 | `@NotNull @DecimalMin("0.0000") @DecimalMax("100.0000") @Digits(integer=3, fraction=4)` |
| 文本 | `@NotBlank @Size(max=...)`，长度按库列上限；AI 消息 `max=300` |
| 枚举 | `@NotNull` + 枚举反序列化；非法值返回 400 |
| 日期 | `@NotNull` + ISO 日期格式；区间 `from <= to` |
| 幂等键 | 请求头 `Idempotency-Key`，正则 `^[A-Za-z0-9_-]{16,64}$` |

4. 跨字段校验（如 `shares` 与 `redeemAll` 互斥、TAA 四类合计 100%）放在 Service/规则引擎，不放在注解；
5. 校验错误不写审计（未进入业务），但记录访问日志。

### 2.8 认证、会话与 CSRF

| 项 | 规范 |
|---|---|
| 登录 | `POST /api/v1/auth/sessions`，`username` + `password`；成功后创建 Session，返回当前用户与 CSRF Token |
| 会话 | `JSESSIONID` Cookie，`HttpOnly`、`SameSite=Lax`、`Secure`（生产 HTTPS）；默认 Tomcat Session，可切 Redis（`app.session.backend=redis`） |
| CSRF | 登录响应与 `GET /api/v1/auth/csrf` 返回 Token；所有 `POST/PUT/PATCH/DELETE` 必须带 `X-CSRF-Token`，否则 403 `AUTH_CSRF_INVALID`。**例外**：AUTH-01、AUTH-02、AUTH-05（注册，登录前无会话）、`/api/v1/ta/**`（无会话）与 `/api/v1/agent/tools/**`（内部令牌）不做 CSRF 校验 |
| 角色 | `user.role`：`INVESTOR` / `ADVISOR`；Controller 使用 `@PreAuthorize`，Service 再做数据范围校验 |
| 登录限流 | Redis 计数，默认同一 `username + IP` 连续失败 5 次锁定 15 分钟，返回 429（可通过配置调整） |
| 登出 | `DELETE /api/v1/auth/sessions/current`，销毁 Session，返回 204 |
| TA 模拟台 | 无登录态；`app.ta.enabled=false` 时所有 `/api/v1/ta/**` 返回 404 `TA_DISABLED` |
| AI 内部工具 | 仅接受 `web-ai-agent` 调用，请求头 `X-Internal-Token` 与配置 `app.agent.internal-token` 一致；不接受浏览器会话 |

### 2.9 授权与数据范围

1. **角色授权**：
   - C 端接口：`INVESTOR`；投顾调用返回 403；
   - FA 端接口：`ADVISOR`；投资者调用返回 403；
   - 双端共用接口（登录、通知、AI 会话）：按登录用户自身数据返回，不区分角色，但 `client_mode` 必须与角色匹配。
2. **归属校验（ER-08）**：投顾访问 `/customers/{customerId}/**` 前，`IClientAccessService.assertAssigned(advisorUserId, customerId)` 校验 `advisor_customer_relation.status=ACTIVE`；不满足返回 403 `CLIENT_NOT_ASSIGNED`，并记录越权访问日志（不写业务审计）。
3. **只读边界**：
   - 投顾可查看客户交易与 TA 状态（TRADE-10），但无 TA 回执接口；
   - 投顾可查看客户组合，但不能代替客户确认跟调（ADVICE-03 仅 INVESTOR）；

4. **演示环境标识**：响应头 `X-Demo-Environment: true`（由配置 `app.demo-environment` 控制），前端据此展示"演示环境 · 非真实交易"（NFR-S5）。

### 2.10 幂等

**强制幂等**的接口必须携带 `Idempotency-Key`（缺失 400，格式错误 400）：

| 接口 | 原因 |
|---|---|
| `POST /api/v1/trade-orders/purchases` | 防重复申购、现金重复冻结 |
| `POST /api/v1/trade-orders/redemptions` | 防重复赎回 |
| `PUT /api/v1/auto-invest-plans/current` | 防重复调整 |
| `POST /api/v1/rebalance-advices` | 防重复推送建议 |
| `POST /api/v1/rebalance-advices/{id}/decisions` | 防重复跟调（BR-29/31） |
| `POST /api/v1/risk-assessments`、`POST /api/v1/customers/{customerId}/risk-assessments` | 防重复提交问卷 |
| `PUT /api/v1/customers/{customerId}/client-portfolios/current` | 防重复保存配置 |
| `POST /api/v1/customers/{customerId}/client-portfolios/current/approval-submissions` | 防重复入审批队列 |
| `POST /api/v1/reports` | 防重复创建报告 |
| `POST /api/v1/reports/{id}/draft-generations` | 防重复触发 AI 生成 |
| `POST /api/v1/reports/{id}/review-submissions` | 防重复提交复核 |
| `POST /api/v1/approval-items/{id}/approvals` | 防重复审批（BR-08） |
| `POST /api/v1/ta/trade-orders/{id}/ta-receipts` | 防重复回执 |
| `POST /api/v1/ta/receipt-batches` | 防重复批量回执 |
| `POST /api/v1/agent/chat` | 防重复发送 AI 消息 |

**处理规则**：

1. 键格式 16–64 位 `[A-Za-z0-9_-]`；`idem_key` 在 `idempotency_key` 表**全局唯一**（`uk_idem_key`），服务端校验本次请求的 `user_id` 与 `request_path` 必须与首次记录一致；
2. 首次请求：写 `idempotency_key`（`request_digest` = 请求体 SHA-256），执行业务，响应体写入 Redis（TTL 7 天）；
3. 重复请求（同键、同用户、同路径、同请求体）：直接回放首次 HTTP 状态与响应体，响应头 `Idempotent-Replayed: true`，不重复产生副作用；
4. 同键不同请求体、或同键被不同用户/不同路径复用：409 `COMMON_IDEMPOTENCY_CONFLICT`，`detail` 说明"幂等键已用于不同请求"；
5. 业务失败（4xx）：是否缓存由错误类型决定——参数/业务校验失败**不缓存**（允许修正后重试）；已产生副作用后的失败（如 TA 回执部分写入）缓存 5 分钟；
6. Redis 不可用：降级为"仅数据库唯一键防重"，重复请求返回 409 `COMMON_IDEMPOTENCY_CONFLICT`（与架构"Redis 不可用时限流降级"同策略）；
7. 过期行（7 天）由平台清理任务物理删除（库设计 4.8.5）。

### 2.12 AI 对话 SSE 约定

`POST /api/v1/agent/chat` 返回 `text/event-stream`（架构 3.4 链路 A、NFR-P4）：

| 项 | 规范 |
|---|---|
| 请求头 | `Accept: text/event-stream`、`X-CSRF-Token`、`Idempotency-Key` |
| 响应头 | `Content-Type: text/event-stream;charset=UTF-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`（Nginx） |
| 事件格式 | `event: <name>\ndata: <json>\n\n` |
| 事件顺序 | `message.started` → 多个 `message.delta` → `message.completed`；异常时 `message.failed` 后结束 |
| 心跳 | 每 15s 发送注释行 `: keep-alive` |
| 落库 | 用户消息在开始前写入 `chat_message`；助手消息在 `message.completed` 前写入；异常时写入已生成内容并标记失败 |
| 降级 | LLM 超时（>10s）或异常 → 关键词路由兜底，`generationMode=FALLBACK`，回复标注"当前为简化模式" |
| 首字时延 | 目标 ≤2s；完整回复 ≤10s（超时降级） |
| 幂等 | 同键重复请求回放首次完整事件序列（Redis 缓存，D-01/2.10） |
| 安全 | 输出落库前 HTML 转义、清理 Markdown 符号、保留换行；不得含可执行交易指令（AD-07/7.3） |

事件负载：

```json

event: message.delta
data: {"text":"【客户组合诊断】\n"}

event: message.completed
data: {"messageId":1002,"generationMode":"LLM","disclaimer":"演示型回复 · 不构成投资建议"}
```

### 2.13 轮询与缓存约定

1. 通知红点、风险未复核计数：前端每 30s 轮询 `GET /notifications/summary` 与 `GET /risk-events/summary`，写操作后主动刷新（Q4/AD-13）；
2. 基金、策略、基金详情读接口使用 Redis 缓存（写失效），响应头返回 `Cache-Control: private, max-age=30`；用户相关数据不缓存；
3. 报告异步生成：前端每 2s 轮询 REPORT-06，最长 60s；超时提示"生成超时，请重试"；
4. 所有列表查询禁止 `SELECT *`；排序统一 `ORDER BY <排序列> DESC, id DESC`（审计/风险/交易等时间序）。

**ASSET-01～03 实施口径（2026-11-17）**：

- 总资产包含冻结资金；累计收益为当前正份额持仓浮盈亏，累计收益率以当前持仓成本为分母，零成本返回 `0.00`。失效/缺失净值返回 409，不将有持仓误计为零。
- 四类配置以持仓市值为分母，按两位小数返回；舍入余差归入市值最大的大类，确保正持仓合计 `100.00`；现金账户四类均为零。Top3 市值相同时按持仓 ID 升序；`shareRatio` 以总资产为分母。
- 无画像 `portfolioRiskLevel=null`，无持仓 `asOfDate=null`；过期画像保留原评级，`matchesProfile=false`。该字段仅表示沿用有效画像，不代表实际持仓全面适配。
- 三条洞察为配置目标偏离、基金/管理人集中度、画像与流动性提醒；缺少完整客户目标配置时明确待完善，不套用原型固定数字。偏离观察阈值 5pp，集中度观察阈值 25%/35%；未关联持久化风险规则时 `sourceRuleCode=null`，不写入风险事件。行业穿透不可用。
- 趋势窗口按上海当前日期减 1/3/6/12 个日历月，包含起止日、排除未来/逻辑删除快照。近30日资产变化按当前日期减30天窗口首尾差；不足两条返回 `0.00`。零基数收益率为 `0.00`，前端解释不可据此判定真实收益。
- 基准采用演示配置 `app.asset.demo-benchmark-daily-percent`（默认 `0.01` 个百分点/日），以区间首个已有快照归零，按日历天线性累计；明确标注非真实指数。无快照时空数组及零摘要，不插值补造账户快照。
- PDF 返回 `application/pdf`、attachment、`Cache-Control: no-store`，包含全部持仓及独立免责声明页；成功生成后与 action=7 / object_type=asset_snapshot 审计同事务提交。使用 PDFBox 3.0.8 和随包 OFL 中文字体，无需依赖操作系统字体。

## 4. 模块接口明细

> 以下按模块给出接口。所有成功响应外层均为 `ResponseDTO`（2.3），示例只展示 `data`；所有错误均为 `ProblemDetail`（2.6）。未特别说明时，投顾访问 `/customers/{customerId}/**` 均先做归属校验。

### 4.1 auth（认证，5 个）

#### AUTH-01 获取 CSRF Token

- **方法与路径**：`GET /api/v1/auth/csrf`；**模块**：auth；**权限**：ANY；**幂等**：-
- **用途**：登录页/会话恢复后获取 CSRF Token；登录成功响应也会返回 Token。
- **请求参数**：无。
- **成功响应**：`200 ResponseDTO<CsrfToken>`

```json
{
  "token": "8f3a...",
  "headerName": "X-CSRF-Token"
}
```

- **业务规则**：Token 与当前 Session 绑定；Session 不存在时仍返回匿名 Token，登录后轮换（架构 2.2）。
- **错误码**：`COMMON_INTERNAL_ERROR`。

#### AUTH-02 登录

- **方法与路径**：`POST /api/v1/auth/sessions`；**模块**：auth；**权限**：匿名；**幂等**：-
- **用途**：用户名/口令登录，创建 Session，返回当前用户与 CSRF Token（NFR-S1）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `username` | string | 是 | 1–64 字符 | `user.username` |
| `password` | string | 是 | 8–64 字符 | 明文仅用于校验，不落库/不返回 |

- **成功响应**：`200 ResponseDTO<LoginResult>`

```json
{
  "user": { "id": 1024, "displayName": "陈女士", "role": "INVESTOR", "riskLevel": "R3" },
  "csrfToken": "8f3a...",
  "csrfHeaderName": "X-CSRF-Token"
}
```

- **业务规则**：
  1. 校验 `password_hash`（bcrypt/argon2id），失败统一返回 `AUTH_INVALID_CREDENTIALS`，不区分用户名/口令错误；
  2. `user.status=DISABLED` 返回 403 `AUTH_ACCOUNT_DISABLED`；
  3. 登录成功写审计（action=6），响应 Set-Cookie `JSESSIONID`；
  4. 连续失败 5 次锁定 15 分钟（Redis，可配置），返回 429；
  5. 按 AD-16，登录后仅在当前站点内进入对应角色域或安全回跳地址；当前站点与响应 `role` 不匹配时提示无权限，提供退出更换账号，不自动跨站点跳转。
  6. 登录失败计数使用数据库命中的规范用户名与客户端 IP，避免 MySQL 等价用户名绕过；Redis 不可用时返回 503，不绕过限流继续登录。
- **错误码**：`AUTH_INVALID_CREDENTIALS`、`AUTH_ACCOUNT_DISABLED`、`AUTH_LOGIN_RATE_LIMITED`、`AUTH_SERVICE_UNAVAILABLE`、`DATABASE_UNAVAILABLE`。

#### AUTH-03 登出

- **方法与路径**：`DELETE /api/v1/auth/sessions/current`；**模块**：auth；**权限**：ANY；**幂等**：-
- **用途**：销毁当前会话。
- **成功响应**：`204` 无 body。
- **业务规则**：清除 Session 与 CSRF Token；重复登出返回 204。
- **错误码**：`COMMON_INTERNAL_ERROR`。

#### AUTH-04 当前用户

- **方法与路径**：`GET /api/v1/auth/me`；**模块**：auth；**权限**：ANY；**幂等**：-
- **用途**：刷新页面/路由守卫恢复登录态与角色。
- **成功响应**：`200 ResponseDTO<UserProfile>`（3.3.1）。
- **业务规则**：未登录返回 401；投顾 `riskLevel` 为 null。
- **错误码**：`AUTH_UNAUTHENTICATED`、`AUTH_SESSION_EXPIRED`。

#### AUTH-05 注册（投资者/投顾）

- **方法与路径**：`POST /api/v1/auth/registrations`；**模块**：auth；**权限**：匿名；**幂等**：-
- **用途**：注册并完成开户初始化（F-U-801~803、D-22）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `username` | string | 是 | 1–64 字符，非空白 | 登录名；全局唯一，注销不释放 |
| `password` | string | 是 | 8–64 字符 | 明文仅用于散列，不落库/不返回 |
| `displayName` | string | 是 | 1–64 字符 | 展示姓名 |
| `role` | Role | 是 | `INVESTOR` / `ADVISOR` | 注册角色 |

- **成功响应**：`201 ResponseDTO<RegistrationResult>`

```json
{
  "userId": 1008,
  "username": "chen",
  "displayName": "陈女士",
  "role": "INVESTOR",
  "customerCode": "C1025",
  "initialCash": "50000.00"
}
```

- **业务规则**：
  1. `username` 由 `uk_username` 保证唯一，重复返回 409 `AUTH_USERNAME_TAKEN`（注销账户不释放，Q7）；
  2. `password` 使用 bcrypt/argon2id 散列存储；长度不满足由 Bean Validation 返回 400 `COMMON_VALIDATION_FAILED`；
  3. `role` 仅 `INVESTOR`/`ADVISOR`，非法值返回 400 `AUTH_ROLE_INVALID`；
  4. 同一本地事务：写 `user`；`INVESTOR` 额外写 `customer`（客户编号自动生成、默认服务状态/优先级）与 `cash_account`（初始现金取配置 `app.registration.investor-demo-cash`，默认 `50000.00`）；`ADVISOR` 不写 `customer`/`cash_account`；
  5. **不创建 `risk_profile`**（首次测评时创建）；**不自动登录、不创建会话**；
  6. 写审计（action=8 提交，`actor_user_id`=新用户、`actor_role`=新角色、`object_type=user`）；
  7. 注册开关 `app.registration.enabled=false` 时返回 404 `AUTH_REGISTRATION_DISABLED`（生产可关闭自助注册）。
- **错误码**：`AUTH_USERNAME_TAKEN`、`AUTH_ROLE_INVALID`、`AUTH_REGISTRATION_DISABLED`、`COMMON_VALIDATION_FAILED`。

### 4.2 user（用户与风险画像，4 个）

#### USER-01 当前用户风险画像

- **错误码**：`COMMON_RESOURCE_NOT_FOUND`。

#### USER-02 获取启用中的测评问卷

- **方法与路径**：`GET /api/v1/risk-questionnaires/active`；**模块**：user；**权限**：INV/ADV；**幂等**：-
- **用途**：风险测评问卷页/投顾代填（F-U-602、TODO-10）。
- **成功响应**：`200 ResponseDTO<RiskQuestionnaire>`（3.3.3）。
- **业务规则**：
  1. 取 `risk_questionnaire.status=1` 的最新版本；
  2. 题目按 `sort_no ASC`；
  3. **选项不返回 `score`**，计分仅在服务端完成，防止前端篡改。
- **错误码**：`USER_RISK_QUESTIONNAIRE_NOT_FOUND`。

#### USER-03 提交风险测评（自测）

- **方法与路径**：`POST /api/v1/risk-assessments`；**模块**：user；**权限**：INV；**幂等**：Y
- **用途**：提交适当性问卷，判定 R1–R5，更新 `risk_profile`（F-U-602、TODO-10、BR-19）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `questionnaireId` | number | 是 | 正数 | 问卷 ID |
| `answers` | array | 是 | 非空 | 作答明细 |
| `answers[].questionId` | number | 是 | 正数 | 题目 ID |
| `answers[].optionIndex` | number | 是 | 0 ≤ index < 选项数 | 选项序号 |

- **成功响应**：`201 ResponseDTO<RiskAssessmentResult>`（3.3.4）。
- **业务规则**：
  1. 每题必须作答且只答一次；否则 422 `USER_RISK_ASSESSMENT_INCOMPLETE`；
  2. 服务端按 `risk_question.options[].score` 汇总 `total_score`，按配置五等分阈值判定 R1–R5（Q2/D-10）；
  3. 写 `risk_assessment`（仅追加）+ 同步更新 `risk_profile`（risk_level、evaluated_at、valid_until）；**`risk_profile` 不存在时按 `user_id` 创建**（注册不预建画像）；
  4. 有效期默认 12 个月（`app.risk-assessment.validity-months=12`）；
  5. 写审计（action=8）。
- **错误码**：`USER_RISK_QUESTIONNAIRE_NOT_FOUND`、`USER_RISK_ASSESSMENT_INCOMPLETE`、`USER_RISK_ANSWER_INVALID`。

**USER-01～03 实施说明（2026-11-16）**：

- 默认以问卷各题最高分之和作为最高可能总分，五等分判级；分界值归较低等级。`app.risk-assessment.levels` 可设置为五个严格递增的非负整数上界，例如 `[32,64,96,128,160]`；为空时按问卷最高分计算，配置必须覆盖最高分。
- `evaluatedAt` 保存 UTC 毫秒时点；`validUntil` 为 `Asia/Shanghai` 测评业务日期加 `validity-months`（默认 12）得到的纯日期；截止日当天有效。
- 服务端忽略客户端附加的分值，答案完整性按问卷题目 ID 集合校验。停用/删除模板返回指定 404；选项序号越界返回 422；字段类型与非负约束不满足返回 400。
- 测评记录、画像更新、action=8 审计、幂等键同事务。用户行锁串行化首次创建和重测；静态 KYC 保留。请求摘要基于校验后的请求 DTO；同键跨用户、跨路径、不同答案均冲突。
- 提交后缓存首次响应 7 天，重复请求返回原 201 和 `Idempotent-Replayed: true`。缓存丢失/不可用时数据库继续防重，重复提交返回 409，客户端引导核对画像。每 10 分钟分批清理本接口到期幂等键（每批最多 1000），不清理测评与审计历史。
- 演示模板通过手工增量 SQL 导入，选项分值不对客户端下发；没有可用模板时如实返回 `USER_RISK_QUESTIONNAIRE_NOT_FOUND`，不在应用启动时生成问卷。
- **既有工程兼容口径**：当前认证、基金和风险模块实际共用 `ResponseDTO(code=0, message="ok", data, timestamp)`，链路标识在 `X-Trace-Id` 响应头。第 2.4 节的目标封装与当前工程存在既有差异；本模块沿用已运行封装，不单独改变全站成功码或新增不兼容响应。

### 4.4 trade（交易、现金、定投与资产，14 个）

#### TRADE-01 申购试算

- **方法与路径**：`POST /api/v1/trade-order-quotes/purchases`；**模块**：trade；**权限**：INV；**幂等**：-
- **用途**：申购弹窗实时展示费率、预计份额、手续费与可用现金（F-U-209、CR-12）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `fundId` | number | 是 | 正数 | 基金 |
| `amount` | string | 是 | ≥ `100.00`，两位小数 | 申购金额 |

- **成功响应**：`200 ResponseDTO<PurchaseQuote>`（3.6.1）。
- **业务规则**：
  1. T 日 = 业务日期；若业务日期非交易日则顺延至下一交易日（D-25）；试算使用 `fund.latest_nav` 作为参考净值，若其净值日 ≠ T 日，`warnings` 追加"净值为最近披露口径"；
  2. 申购费 = `amount × fee_purchase / 100`；预计份额 = `(amount − 申购费) / latest_nav`（CR-12，四舍五入 4 位）；
  3. 可用现金不足**不作为试算失败**，在 `warnings` 中提示；提交时才拦截；
  4. 客户存在有效风险画像且基金风险等级高于画像时 `riskAcknowledgmentRequired=true`（BR-33）；**未测评/画像已过期时 `riskAcknowledgmentRequired=false`，`warnings` 提示"尚未完成有效风险测评，建议先测评"，不阻断**（D-28）；
  5. 限购/暂停申购时 `warnings` 提示"TA 可能确认失败"（BR-35）。
- **错误码**：`FUND_NOT_FOUND`、`TRADE_AMOUNT_BELOW_MIN`。

#### TRADE-02 赎回试算

- **方法与路径**：`POST /api/v1/trade-order-quotes/redemptions`；**模块**：trade；**权限**：INV；**幂等**：-
- **用途**：赎回弹窗展示可赎回份额、预计到账与费用（F-U-403、CR-13）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `fundId` | number | 是 | 正数 | 基金 |
| `shares` | string | 条件 | > 0，四位小数；与 `redeemAll` 互斥 | 赎回份额 |
| `redeemAll` | boolean | 条件 | true 时忽略 `shares` | 全部赎回 |

- **成功响应**：`200 ResponseDTO<RedemptionQuote>`（3.6.2）。
- **业务规则**：
  1. 必须持有该基金且 `holding.shares > 0`，否则 404 `TRADE_HOLDING_NOT_FOUND`；
  2. `shares` 超过可赎回份额返回 422 `TRADE_SHARES_EXCEEDED`；
  3. `redeemAll=true` 时 `shares=holding.shares`；
  4. 赎回总额 = `shares × latest_nav`；赎回费 = 总额 × `fee_redeem / 100`；预计到账 = 总额 − 费用（CR-13）；
  5. 暂停赎回时 `warnings` 提示"TA 可能确认失败"。
- **错误码**：`FUND_NOT_FOUND`、`TRADE_HOLDING_NOT_FOUND`、`TRADE_SHARES_EXCEEDED`、`TRADE_REDEEM_ARGUMENT_CONFLICT`。

#### TRADE-03 提交基金申购

- **方法与路径**：`POST /api/v1/trade-orders/purchases`；**模块**：trade；**权限**：INV；**幂等**：Y
- **用途**：创建申购交易（PENDING_TA），冻结可用现金，持仓与现金余额不变（F-U-209、BR-32/33/34/36、DF-15）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `fundId` | number | 是 | 正数 | 基金 |
| `amount` | string | 是 | ≥ `100.00`，两位小数 | 申购金额 |
| `riskAcknowledged` | boolean | 否 | 默认 false | 风险高于画像时须为 true（BR-33） |

- **成功响应**：`201 ResponseDTO<TradeOrderDetail>`（3.6.4）。
- **业务规则**：
  1. 单笔金额 ≥ ¥100；金额不得超过可用现金（`cash_balance − Σ PENDING_TA.freeze_amount`），否则 422（BR-32、ER-16）；
  2. 客户存在有效风险画像且基金风险等级 > 客户风险等级时，`riskAcknowledged=true` 才可提交，否则 422（BR-33）；**未测评/画像已过期时不做风险确认拦截，仅按 D-28 提示**；
  3. 限购/暂停申购**允许提交**，但响应 `remark` 或后续 TA 失败体现（BR-35）；
  4. 同一本地事务：写 `trade_order`（type=PURCHASE、status=PENDING_TA、`trade_date`=业务日期，**非交易日顺延至下一交易日**、freeze_amount=amount、total_amount_in=amount、total_fee=申购费）+ `trade_order_item`（direction=BUY、amount、shares=0、fee）+ 写审计；**不扣减 `cash_account.cash_balance`**；
  5. 委托编号 `T-YYYYMMDD-NNN` 由 `platform` 序号器生成，唯一索引兜底；
  6. 返回 `taReceipt=null`；前端展示"待登记确认"。
- **错误码**：`FUND_NOT_FOUND`、`TRADE_AMOUNT_BELOW_MIN`、`TRADE_AVAILABLE_CASH_INSUFFICIENT`、`TRADE_RISK_ACKNOWLEDGEMENT_REQUIRED`、`COMMON_IDEMPOTENCY_CONFLICT`。

#### TRADE-04 提交基金赎回

- **方法与路径**：`POST /api/v1/trade-orders/redemptions`；**模块**：trade；**权限**：INV；**幂等**：Y
- **用途**：创建赎回交易（PENDING_TA），TA 确认前持仓与现金不变（F-U-403、BR-32/34/36）。
- **请求体**：同 TRADE-02。
- **成功响应**：`201 ResponseDTO<TradeOrderDetail>`。
- **业务规则**：
  1. 必须持有且份额足够，否则 422 `TRADE_SHARES_EXCEEDED`（ER-14）；
  2. 同一本地事务：写 `trade_order`（type=REDEMPTION、status=PENDING_TA、`trade_date`=业务日期，**非交易日顺延至下一交易日**、freeze_amount=0、total_amount_out=赎回总额估算、total_fee=赎回费估算）+ `trade_order_item`（direction=SELL、shares、amount=0、fee）+ 审计；

- **用途**：整单确认跟调或暂不跟调（F-U-306/307、BR-29/31、DF-12/14）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `decision` | AdviceDecision | 是 | `FOLLOW` / `DECLINE` | 跟调决定 |


  1. 建议必须属于当前用户且状态为 `PENDING`，否则 409 `ADVICE_NOT_PENDING`；
  2. `validUntil < 业务日期` 时置 `EXPIRED` 并返回 422 `ADVICE_EXPIRED`（ER-13）；

     - 写审计（action=8）；
  4. `DECLINE`：建议置 `REJECTED`，不创建交易，持仓不变（BR-29）；
  5. 不操作到期由调度任务置 `EXPIRED`（BR-30/AD-10），持仓保持不变。

#### ADVICE-04 投顾生成并推送调仓建议

- **方法与路径**：`POST /api/v1/rebalance-advices`；**模块**：advice；**权限**：ADV；**幂等**：Y
- **用途**：投顾在客户组合抽屉发起推送，后端生成明细、金额、费用与 3 个交易日有效期（F-A-412、BR-28、DF-11）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `clientPortfolioId` | number | 是 | 正数 | 客户组合（决定客户、模型组合、策略与目标权重） |
| `basis` | string | 否 | ≤255 字符 | 建议依据；不传由系统生成"基于 {风险等级} 画像与最新持仓" |
| `reason` | string | 否 | ≤512 字符 | 调出调入理由；不传由系统生成摘要 |

- **成功响应**：`201 ResponseDTO<RebalanceAdviceDetail>`。
- **业务规则**：
  1. 归属校验：客户必须属于当前投顾（ER-08）；
  2. 目标权重复用客户组合"带内微调目标权重"；若客户组合不存在，返回 404 `PORTFOLIO_CLIENT_NOT_FOUND`；
  3. 明细计算（后端 `rule` 引擎，D-04）：
     - 当前基金权重 = `holding.market_value / 客户总资产 × 100`；
     - 目标基金权重 = 策略 `strategy_fund_position.target_weight` 按客户目标大类权重等比缩放；
     - `target > current` 且 `current=0` → `BUY`；`target > current` 且 `current>0` → `INCREASE`；`target < current` → `SELL`；
     - 金额 = `|目标金额 − 当前金额|`，保留 2 位；权重差 ≤0.0001% 的基金不生成明细；
     - `asset_before`/`asset_after` 为四类实际权重 → 目标权重，JSON 键固定 `equity`/`bond`/`money`/`gold`；
     - 汇总金额、预计费用、换手率（`(调出+调入)/2/总资产×100`，见 6.7）；
  4. `valid_until` 由 `trading_day` 计算业务日期后的第 3 个交易日（BR-30）；`pushed_at` 为当前时间；`status=PENDING`；
  5. 无任何需要调整的基金时返回 422 `ADVICE_NO_REBALANCE_NEEDED`；
  6. 允许同一客户存在多条待确认建议，按推送时间倒序展示；建议推送后不可修改（库设计 4.3.8）；
  7. 写审计（action=1 生成）。
- **错误码**：`PORTFOLIO_CLIENT_NOT_FOUND`、`CLIENT_NOT_ASSIGNED`、`ADVICE_NO_REBALANCE_NEEDED`、`COMMON_IDEMPOTENCY_CONFLICT`。

|---|---|---|---|---|

- **方法与路径**：`POST /api/v1/reports/{reportId}/draft-generations`；**模块**：report；**权限**：ADV；**幂等**：Y
- **用途**：AI 生成报告初稿；返回 202 + 任务 ID，前端轮询 REPORT-06（F-A-606/607、BR-09/10、D-04/D-05）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `strategyChangeReason` | string | 条件 | ≤512 字符 | 关联策略与客户当前策略不一致时必填；作为本次 AI 生成输入，并由 AI 在正文"策略与配置框架"节说明更换理由（BR-27） |

- **成功响应**：`202 ResponseDTO<DraftGenerationAccepted>`

```json
{
  "generationId": 501,
  "reportId": 31,
  "status": "PENDING",
  "requestedAt": "2026-11-16T03:20:11.123Z"
}
```

- **业务规则**：
  1. 报告属于当前投顾；`status` 必须是 `TEMPLATE_PREVIEW` 或 `AI_DRAFT`，否则 409 `REPORT_NOT_EDITABLE`；
  2. 前置校验（BR-09，前两步系统自动）：客户信息与权限验证、数据与来源校验（客户 KYC、持仓、策略、SAA/TAA 存在）；失败返回 422 `REPORT_PRECHECK_FAILED`；

  5. 写 `event_outbox`：`event_type=report.draft.generate`、`aggregate_type=report`、`aggregate_id=reportId`、`payload` 含报告/客户/策略/请求人/`strategyChangeReason`/`traceId`、`dispatch_status=PENDING`；返回 `generationId=outbox.id`；同时将 `strategyChangeReason` 写入本次 `audit_log.detail`（BR-27 留痕，可追溯）；
  6. 调度 worker 调用 `web-ai-agent`，成功后写 `report.content`、`report.generated_at`、`report.status=AI_DRAFT`，并将 outbox 置 `DISPATCHED`；失败置 `FAILED` 并按 `retry_count/next_retry_at` 退避重试，**自动重试最多 3 次**，超过后停止自动重试并等待用户手动重新触发（D-21）；

- **错误码**：`REPORT_NOT_FOUND`、`REPORT_NOT_EDITABLE`、`REPORT_PRECHECK_FAILED`、`REPORT_STRATEGY_CHANGE_REASON_REQUIRED`、`REPORT_DRAFT_ALREADY_GENERATING`、`COMMON_IDEMPOTENCY_CONFLICT`。

#### REPORT-06 轮询报告生成状态

- **方法与路径**：`GET /api/v1/reports/{reportId}/draft-generations/{generationId}`；**模块**：report；**权限**：ADV；**幂等**：-
- **用途**：轮询生成状态（2s 间隔，最长 60s）。
- **成功响应**：`200 ResponseDTO<DraftGenerationStatusResult>`

```json
{
  "generationId": 501,
  "reportId": 31,
  "status": "SUCCEEDED",
  "reportStatus": "AI_DRAFT",
  "failureReason": null,
  "retryable": false,
  "requestedAt": "2026-11-16T03:20:11.123Z",
  "completedAt": "2026-11-16T03:20:18.456Z"
}
```

- **业务规则**：
  1. 任务必须属于该报告且报告属于当前投顾；
  2. 状态推导（D-05）：`report.generated_at != epoch` 且 outbox 已派发 → `SUCCEEDED`；outbox `dispatch_status=FAILED` → `FAILED`；否则 `PENDING`（含排队/生成中，无 RUNNING 细分）；
  3. 生成成功时同步返回 `reportStatus=AI_DRAFT`；
  4. 失败时 `failureReason` 为脱敏错误摘要，前端提示"生成失败，请重试"；
  5. `retryable`：`FAILED` 时为 true（可手动重新触发 REPORT-05），`PENDING`/`SUCCEEDED` 时为 false；自动重试最多 3 次（D-21）。
- **错误码**：`REPORT_NOT_FOUND`、`REPORT_DRAFT_GENERATION_NOT_FOUND`。

#### REPORT-07 提交报告复核

- **方法与路径**：`POST /api/v1/reports/{reportId}/review-submissions`；**模块**：report；**权限**：ADV；**幂等**：Y
- **用途**：AI 草案提交复核/合规审批，进入审批队列（F-A-607、BR-10、DF-05）。

- **业务规则**：
  1. 报告属于当前投顾且 `status=AI_DRAFT`，否则 409 `REPORT_REVIEW_SUBMIT_INVALID`；
  2. 报告状态置 `UNDER_REVIEW`；

#### TA-03 逐笔提交 TA 回执

- **方法与路径**：`POST /api/v1/ta/trade-orders/{orderId}/ta-receipts`；**模块**：ta；**权限**：TA；**幂等**：Y
- **用途**：模拟第三方 TA 确认成功/失败，推进交易终态并更新持仓现金（F-D-04、BR-34/35/37、DF-13）。
- **请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `result` | TaResult | 是 | `SUCCESS` / `FAILED` | 确认结果 |
| `failReason` | TaFailReason | 条件 | `FAILED` 必填，取值 1–5 | 失败原因 |

- **成功响应**：`200 ResponseDTO<TradeOrderDetail>`，含 `taReceipt`。
- **业务规则**：
  1. 订单必须存在且 `status=PENDING_TA`，否则 409 `TA_TRADE_ORDER_NOT_PENDING`（ER-17）；
  2. 回执字段全部由服务端计算（D-07）：`receiptNo=TA{yyyyMMdd}{NNN}`、`confirmDate`=T+1 交易日、`navDate=trade_date`、`unitNav`=该基金 T 日 `fund_nav.unit_nav`；单基金订单写实际净值，调仓单因含多基金置 `0.0000`，各基金净值由明细 `confirmed_amount/confirmed_shares` 推导（GAP-22）；缺 T 日净值返回 422 `TA_NAV_NOT_AVAILABLE`；
  3. 确认金额/份额按 CR-15：申购确认份额=`(申购金额−费用)/T日净值`；赎回确认金额=`赎回份额×T日净值`；调仓按明细逐基金计算；
  4. `SUCCESS`：
     - 订单 `CONFIRMED`；明细回填 `confirmed_amount`/`confirmed_shares`；
     - 申购：`cash_balance −= 申购金额`，持仓份额增加，`cost_amount += 金额 − 费用`；
     - 赎回：`cash_balance += 确认金额 − 费用`，持仓份额减少（成本按赎回比例冲减，见 6.12）；
     - 调仓：按明细逐基金按 T 日净值确认份额/金额；买入按 `金额 − 费用` 增加 `cost_amount`，卖出按比例冲减；**现金按净额结算 `cash_balance += 调出确认金额 − 调入确认金额 − 费用`**（BR-37/DDR-04，D-23）；
     - 关联建议 `advice_id != 0` 时关注 outbox 事件 `trade.confirmed`，`advice` 订阅后置建议 `COMPLETED`（F-U-312；trade 不直接依赖 advice）；
  5. `FAILED`：订单 `FAILED`，写 `fail_reason`；持仓与现金不变，冻结自动释放（BR-35）；写 outbox 事件 `trade.failed`，`advice` 订阅后置建议 `TA_FAILED`；
  6. 写 `ta_receipt`（1:1 终态）+ 审计（actor_role=3、actor_user_id=0、action=5）；
  7. 整单成功/失败，不支持部分成功（库设计 Q5）。
- **错误码**：`TA_DISABLED`、`TA_TRADE_ORDER_NOT_PENDING`、`TA_FAIL_REASON_REQUIRED`、`TA_FAIL_REASON_INVALID`、`TA_NAV_NOT_AVAILABLE`、`COMMON_IDEMPOTENCY_CONFLICT`。

#### TA-04 批量确认成功

## 6. 评审问题与确认记录

> 以下问题在接口层已给出可执行的设计口径。**Q1~Q13 已于 2026-11-16 全部确认（D-09~D-21）**，本章保留决策记录与确认结论，供评审追溯。

### 6.1 Q1 策略 6 项关键指标的派生公式（已确认）

库设计 `strategy` 无收益/波动/回撤/夏普/容量/费率列。当前接口按以下演示口径派生：

- `return1y` = Σ（基金目标权重 × 基金 `return_1y`）；
- `annualizedVolatility` = Σ（权重 × 基金年化波动率），不计协方差；
- `maxDrawdown` = Σ（权重 × 基金最大回撤），不计相关性；
- `sharpe` =（`return1y` − 无风险利率）/ `annualizedVolatility`，无风险利率取配置；
- `capacity` = Σ（基金 `fund_size` × 该基金在策略中的权重）；
- `weightedFee` = Σ（权重 × `fund.fee_manage`）。

**确认结论（D-09）**：接受上述简化派生公式；前端策略表保持 6 项指标展示。

### 6.2 Q2 风险测评评分阈值（已确认）

`risk_question.options` 存单题得分，但库中无"总分 → R1–R5"阈值配置。当前设计为应用配置 `app.risk-assessment.levels`（默认按总分五等分）。

**确认结论（D-10）**：采用应用配置五等分阈值（`app.risk-assessment.levels`），测评有效期固定 12 个月；边界分数归入较低风险等级。

### 6.3 Q3 客户"区间收益"口径（已确认）

客户列表/详情的 `returnRate` 采用近 1 年区间收益口径。

**确认结论（D-13）**：采用近 1 年 `asset_snapshot` 首尾总资产变化率，不剔除申赎现金流；不再使用持仓累计成本收益率口径。

### 6.4 Q4 客户配置提交审批的粒度与"最近复核"（已确认）

当前 PORTFOLIO-07 默认按 SAA/TAA/FUND 三层各生成一条 `approval_item`；PORTFOLIO-06 保存配置时更新 `last_reviewed_at`。

**确认结论（D-11）**：①一次提交按 SAA/TAA/FUND 三层各生成一条 `approval_item`；②保存配置即视为一次复核，刷新 `last_reviewed_at`。

### 6.5 Q5 "组合风险等级 R3"的语义（已确认）

资产总览展示"组合风险等级 R3 平衡型（匹配客户画像）"，但库中只有客户 KYC 风险等级，无组合风险度量。

**确认结论（D-12）**：直接沿用 `risk_profile.risk_level` 展示，并标注"匹配客户画像"；不引入组合风险计算。

### 6.6 Q6 AI 客户洞察与今日建议的生成方式（已确认）

当前设计：客户 360 `insights` 与工作台 `suggestions` 由 `rule` 引擎生成结构化文本，不调用 LLM；AI 对话才走 AGENT-04。

**确认结论（D-14）**：客户 360 洞察与工作台建议由 `rule` 引擎生成；只有 AI 对话走 AGENT-04。

### 6.7 Q7 换手率公式（已确认）

当前 `turnoverRate = (调出金额 + 调入金额) / 2 / 客户总资产 × 100`。

**确认结论（D-15）**：采用双边均值口径 `(调出金额 + 调入金额) / 2 / 客户总资产 × 100`。

### 6.8 Q8 跟调确认是否校验可用现金（已确认）

当前 ADVICE-03 `FOLLOW` 除 BR-31 在途互斥外，还校验 `freeze_amount ≤ 可用现金`。

**确认结论（D-16）**：保留可用现金校验；冻结金额超过可用现金时返回 422 `TRADE_AVAILABLE_CASH_INSUFFICIENT`。

### 6.9 Q9 TAA ±1pp 对冲大类选择规则（已确认）

当前拟采用：从"调整后仍在 SAA 区间内、且当前 TAA 权重最大"的其他大类扣减 1pp；同权重按 `assetClass` 升序。

**确认结论（D-17）**：采用后端确定性对冲规则；无法完成对冲时返回 422 `STRATEGY_TAA_COMPENSATION_FAILED`。

### 6.10 Q10 单行业穿透 ≤30%（已确认）

库设计无基金行业持仓字段，本期无法计算行业集中度。

**确认结论（D-18）**：本期不计算单行业穿透，接口返回 `industryConstraintAvailable=false`；不新增行业表/字段。

### 6.11 Q11 TA 模拟台的数据范围（已确认）

无登录态，模拟台需明确聚合范围。

**确认结论（D-19）**：演示环境固定只有一个投资者账户，模拟台聚合该账户的现金与待登记交易；多账户扩展不在本期。

### 6.12 Q12 赎回确认的持仓成本冲减（已确认）

当前按赎回份额比例冲减 `holding.cost_amount`：`cost_amount -= cost_amount × 赎回份额 / 赎回前份额`；全部赎回时成本归零、保留零份额行。

**确认结论（D-20）**：采用比例冲减口径；全部赎回时成本归零并保留零份额行。

### 6.13 Q13 报告生成失败与重试（已确认）

当前 outbox 自动退避重试（`retry_count/next_retry_at`），用户可重新触发 REPORT-05。

**确认结论（D-21）**：自动退避重试最多 3 次；REPORT-06 返回 `retryable`；用户可手动重新触发；失败不保留部分内容，重试从零生成。
